# 崇明微信小程序进度记录

## 一、项目背景情况

当前目标为本地可运行的微信小程序 Demo，以崇明户外打卡点的发现、个人资料、路线与安排为主要功能骨架。当前不接入正式服务端，用户、个人资料等数据通过 Sample 数据和微信本地 Storage 模拟；数据访问保留 Model、Repository 与 Page 的分层。

应用支持访客先浏览发现页，用户需要访问或修改个人内容时再主动登录。登录使用演示登录名映射内部 `userId`，不模拟真实微信 `openid`。

## 二、项目现状

### 1. 页面与导航

- 发现页为默认启动页，访客无需登录即可浏览。
- 底部 TabBar 包含发现、收藏、我的、编辑。
- 登录页为非 Tab 页面，由“我的”等入口主动进入。
- 打卡点详情页可通过 `checkpointId + version` 导航访问。

### 2. 用户与个人资料

- 已建立 `User`、`UserProfile` 工厂。
- 已建立 Sample 登录名到内部 `userId` 的映射与本地持久化。
- 已建立 `UserRepository`、`UserProfileRepository`。
- “我的”页面可显示当前用户、个人资料和未登录状态。
- 已实现基础信息编辑页，可修改头像和展示用户名，并主动退出登录。
- 已实现个人资料编辑页，可修改年龄阶段、技能、兴趣和简介。
- 基础信息与个人资料编辑页已接入未保存退出提醒；保存成功或恢复原值后不再提示。
- 技能和兴趣允许自由输入；Repository 从完整 Sample 候选池中随机抽取建议标签。
- 编辑页返回后，“我的”通过 `onShow()` 重新读取最新数据。

### 3. 日历与 Schedule

- “我的”页面下方已加入静态月历组件。
- 月历显示当前年月、星期、固定六行日期网格和当天标记。
- 当前月历尚未接入 Schedule 数据、日期选择或月份切换。
- 已建立 `Schedule` 工厂。
- Schedule 使用统一的 `targetRef: { type, id, version }`。
- 当前目标类型为 `CHECKPOINT` 与 `PERSONAL_ROUTE`。
- Checkpoint 目标未来由 Checkpoint Repository 解析；PersonalRoute 目标未来由用户本地 Workspace Repository 解析。
- 相同 `type + id + version` 必须指向不可变且可长期查询的版本对象。

## 三、项目计划情况

### 1. 已确认修改项

#### 发现页搜索栏

- 在发现页增加搜索栏。
- 搜索范围、匹配字段、实时搜索或提交搜索方式尚待实现前确认。

### 2. Schedule 近期实现顺序

1. 复查并确认 `Schedule` 工厂字段与状态约束。
2. 建立 Sample Schedule 数据。
3. 建立 `ScheduleRepository`，实现按用户、月份、日期和 ID 查询。
4. 建立统一的 Schedule Target Resolver，按目标类型分流到对应 Repository。
5. 让“我的”静态月历根据当月 Schedule 数据显示日期标记。
6. 建立“我的安排”页面：上方交互月历，下方显示选中日期的安排列表。
7. 点击安排进入独立的安排创建/编辑页。

### 3. 现有骨架待办

- 收藏页仍为占位页面。
- 编辑 Tab 仍为创建和管理内容的占位入口。
- 打卡点详情页“创建安排”按钮尚未接入业务流程。
- 日历尚未支持月份切换、日期选择、安排数量或状态标记。
- PersonalRoute、PersonalRouteDraft 与不可变版本 Repository 尚未定义。
- Schedule Target Resolver 尚未建立。
- 安排创建、编辑、取消、完成与招募状态流转尚未实现。
- Checkpoint 与 PersonalRoute 版本更新后的过期提示、主动迁移机制尚未实现。
- 当前头像使用临时路径，尚未实现正式资源持久化。
- 发现页和详情页仍使用图片占位资源。

### 4. 验证方式

- 轻量 UI 和交互修改由用户在微信开发者工具中编译检查。
- Codex 默认只执行静态语法、JSON、引用和 Git 差异检查，并描述预期运行结果。
