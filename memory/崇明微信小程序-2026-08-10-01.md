# 崇明微信小程序进度记录

## 一、项目背景情况

当前目标为本地可运行的微信小程序 Demo，以崇明户外打卡点发现、个人资料、个人路线与日程安排为主要功能骨架。当前不接入正式服务端，用户与 Schedule 等数据通过 Sample 数据和微信本地 Storage 模拟；代码继续保留 Model、Repository、Page 与 WXML 的分层。

Schedule 使用统一目标引用：

```js
targetRef: {
  type,
  id,
  version,
}
```

`CHECKPOINT` 从 Checkpoint Repository 解析；`PERSONAL_ROUTE` 计划在路线结构完成后，从用户本地 Workspace Repository 导入和解析。

## 二、项目现状

### 1. Schedule 数据层

- 已建立 `Schedule` 工厂及状态组合验证。
- 已建立本地 Storage 支持的 `ScheduleRepository`。
- Repository 已实现 `findById()`、`findByOwnerAndRange()`、`create()` 和 `update()`。
- Schedule ID 使用 `nextScheduleSequence` 生成连续的本地演示 ID。
- 日期查询使用当天本地时间范围，并返回与该范围发生重叠的安排。

### 2. Schedule 编辑页

- 已建立共用的 Schedule 新建/编辑页面。
- 已支持选择 Sample Checkpoint、开始和结束时间、可见性、招募状态、计划状态、共享备注和私人备注。
- 新建模式调用 `ScheduleRepository.create()`；编辑模式调用 `update()`。
- 编辑已有安排时，目标引用当前保持只读。
- 已加入未保存退出提醒。
- 当前只真正支持 `CHECKPOINT`，尚未接入 `PERSONAL_ROUTE`。

### 3. 日期安排列表页

- 已从编辑页成功创建 Schedule，并能在开发者工具的 Console/Storage 中确认记录。
- `loadSchedulesForSelectedDate()` 已接入 `createLocalDayRange()` 与 `findByOwnerAndRange()`。
- 查询结果已通过 `this.setData({ schedules })` 提供给 WXML。
- 当前 WXML 仍使用 `timeText`、`targetTitle`、`statusText`，但 Repository 返回的原始 Schedule 不包含这些展示字段，因此安排卡片显示尚未完成。

## 三、项目计划情况

### Schedule 页面剩余 TODO

1. **增加目标数据类型选择字段**
   - 在编辑页允许选择 `CHECKPOINT` 或 `PERSONAL_ROUTE`。
   - 选择结果写入 `targetRef.type`。
   - 第一阶段可只启用 `CHECKPOINT`；路线选项根据路线数据层进度决定是否禁用。

2. **修改选择打卡点逻辑**
   - 当目标类型为 `CHECKPOINT` 时，才展示并加载打卡点选择控件。
   - 选择结果需要同时保存 `checkpointId` 与 `version`。
   - 具体筛选、搜索及展示交互仍待后续确认。

3. **添加 Personal Route 支持**
   - 此项延后处理。
   - 前置条件为完成 Personal Route 数据结构、不可变版本结构和用户 Workspace Repository。
   - 完成前置结构后，编辑页从当前用户 Workspace 导入可选择路线，并生成 `PERSONAL_ROUTE + id + version` 引用。

4. **修改 Schedule 显示卡片**
   - 将原始时间戳转换成便于阅读的时间范围。
   - 根据 `targetRef.type + id + version` 获取目标标题。
   - 将 `planningStatus` 等枚举转换为中文展示文本。
   - 生成 WXML 当前所需的 `timeText`、`targetTitle` 和 `statusText`，或同步调整卡片字段绑定。

### 推荐实现顺序

1. 先完成 Schedule 卡片的最小原始数据显示，确认查询与 WXML 数据链路。
2. 增加目标数据类型选择字段。
3. 按类型调整 Checkpoint 选择逻辑。
4. 完成路线结构与用户 Workspace Repository 后，再接入 Personal Route。
5. 最后统一目标解析和卡片展示映射。
