## 一、项目背景情况

项目是面向崇明户外探索的微信小程序 Demo，核心内容包括公开 Checkpoint、公开 Route、个人草稿、Schedule、收藏和内容互动。当前仍以 Sample Seed 和微信本地 Storage 运行，不包含真实服务端、真实审核后台、并发事务或跨设备媒体存储。

当前保持的数据边界：

- 页面不直接操作 Storage，通过 Repository 或 Query 获取数据。
- Checkpoint 与 Route 的稳定身份、公开版本和可编辑草稿分开保存。
- 点赞、收藏等用户行为使用独立交互记录，公开对象暂时保留聚合计数。
- Comment 是独立辅助结构，通过 `targetRef = { type, id }` 关联公开 Checkpoint/Route，不绑定具体版本。
- Schedule 仍通过带版本的 `targetRef` 引用目标；来源草稿被引用后，修改时采用检查并提示的策略，而不是创建 Schedule 时一律冻结快照。
- 当前审核均为本地模拟流程，不能视为真实权限或内容安全能力。

### 3. Comment 数据模型

#### CommentTargetRef

```js
{
  type: 'CHECKPOINT' | 'ROUTE',
  id: string
}
```

Comment 只绑定内容稳定身份，不绑定版本。页面显示目标信息时，重新解析该身份当前对应的公开内容。

#### Comment

```js
{
  id,
  authorUserId,
  targetRef,
  content,
  rootCommentId,
  replyToCommentId,
  likeCount,
  status,
  createdAtEpochMillis,
  updatedAtEpochMillis
}
```

回复关系语义：

- 根评论：`rootCommentId = null`，`replyToCommentId = null`。
- B 回复根评论 A：B 的两个引用都指向 A。
- C 回复 B：`rootCommentId = A`，`replyToCommentId = B`。
- 数据能保留回复链，但计划中的移动端展示采用“根评论 + 扁平回复列表”，避免无限层级缩进。

#### CommentStatus

```js
IN_REVIEW
VISIBLE
REJECTED
DELETED
```

- 新评论默认进入 `IN_REVIEW`。
- 当前本地模拟审核固定返回 `true`，随后由统一审核结果方法转为 `VISIBLE`。
- `REJECTED` 与 `DELETED` 分开表达审核拒绝和用户删除。
- 只有 `VISIBLE` 评论计入公开数量，并允许成为回复或点赞对象。

#### CommentLike

```js
{
  commentId,
  userId,
  createdAtEpochMillis
}
```

- 点赞明细是事实来源。
- `Comment.likeCount` 是便于展示的聚合缓存。
- 加载状态时会去除重复点赞、过滤找不到评论的悬空点赞，并根据点赞明细校准 `likeCount`。
- `findLikeSummary(commentId, userId)` 返回单条评论的 `{ likeCount, isLiked }`，适合局部刷新；列表页后续应批量组合 DTO，避免逐条重复读取 Storage。

### 4. Comment Repository

当前使用单一 Storage 状态：

```js
{
  schemaVersion: 1,
  nextCommentSequence: 1,
  comments: [],
  likes: []
}
```

评论和点赞位于同一状态中，使切换点赞与更新 `likeCount` 能一次持久化。

现有接口：

- `findById(commentId)`
- `findByTarget(targetRef)`
- `countByTarget(targetRef)`
- `createRoot(targetRef, content)`
- `createReply(replyToCommentId, content)`
- `resolveReview(commentId, approved)`
- `softDeleteForCurrentUser(commentId)`
- `toggleLikeForCurrentUser(commentId)`
- `findLikeSummary(commentId, userId)`

当前审核流程：

1. `createRoot/createReply` 先保存 `IN_REVIEW` 评论。
2. 调用本地 `reviewComment()`。
3. `reviewComment()` 当前固定返回 `true`。
4. `resolveReview()` 统一将状态登记为 `VISIBLE` 或 `REJECTED`。

接入真实服务后，应替换审核调用并将可信审核判定移到服务端；不能允许普通客户端直接决定 `approved`。
