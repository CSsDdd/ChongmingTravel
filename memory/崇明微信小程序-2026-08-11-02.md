# 崇明微信小程序进度记录

## 一、项目背景情况

当前项目为本地可运行的微信小程序 Demo，主要功能包括崇明户外打卡点发现、用户资料、路线与日程安排。当前使用 Sample 数据和微信本地 Storage 模拟数据源，并保持 Model、Repository、Page、Component 与 WXML/WXSS 分层。

Schedule 使用统一目标引用：

```js
targetRef: {
  type,
  id,
  version,
}
```

当前实际支持的目标类型只有 `CHECKPOINT`；`PERSONAL_ROUTE` 等待路线和 Workspace 数据结构完成后再接入。

## 五、下一功能：Checkpoint 选择页

### 目标

建立独立的 Schedule 目标选择页，替换编辑页当前直接加载全部 Sample Checkpoint 的临时选单。

建议新分支：

```text
feat/checkpoint-picker
```

建议第一阶段范围：

1. 建立独立 Checkpoint 选择 Page。
2. 从 Checkpoint Repository 获取全部可选项。
3. 提供简单本地文本搜索，匹配标题、地点、标签和简介。
4. 点击项目后返回 `id + version + title`。
5. Schedule 编辑页接收结果并写入 `targetRef`。
6. 搜索暂时采用线性遍历和 `String.includes()`，不引入分词、拼音或服务端全文搜索。

页面间返回结果可考虑使用 `wx.navigateTo()` 的 `EventChannel`。新对话开始后应先确认具体交互与接口，再修改代码。

## 六、后续独立功能

### 1. Checkpoint 素材区 / Workspace

- 用户提出将 Workspace 分为 Checkpoint 素材与 Route 草稿。
- Checkpoint 不应从公共数据源物理移动到 Workspace；素材区保存外部 Checkpoint 的引用和可选私人信息。
- Schedule 最终仍保存原始 `CHECKPOINT + id + version`，不依赖临时素材 ID。
- 需要先决定现有“收藏”功能是改造成素材区，还是与素材区保持不同语义。
- 推荐在 Checkpoint Picker 完成后单开分支实现。

### 2. Personal Route

- 完成 Route Model、版本结构和用户 Workspace Repository 后接入。
- Route 与 Checkpoint 可以在选择页统一成展示项，但不应强行共享同一个底层 Model。

### 3. 他人日程与可见性

- 当前 Schedule Repository 的 `findByOwnerAndRange()` 会返回指定所有者范围内的全部 Schedule。
- 在允许通过页面参数查看其他用户前，必须增加结合访问者和 `visibility` 的安全查询接口。
