# 崇明微信小程序进度记录

## 一、项目背景情况

当前项目是本地可运行的微信小程序 Demo，主要覆盖崇明户外打卡点发现、用户资料、日程安排，以及正在建设的用户内容编辑能力。

当前仍以 Sample Seed 和微信本地 Storage 模拟数据源，不包含真实服务端、真实审核后台或跨设备素材存储。代码继续保持 Model、Repository、Page、Component 与 WXML/WXSS 的分层；页面不直接承担底层数据持久化逻辑。

Checkpoint 采用“轻量聚合 + 版本详情”的结构：

- `Checkpoint` 保存稳定身份与版本指针。
- `CheckpointVersion` 保存某一版本的标题、简介、图片、位置、标签等详细信息。
- `CheckpointDraft` 保存用户当前草稿的版本和审核状态。
- Draft 与 Public 共享 `checkpointId`，但使用独立 Storage 状态。

### 2. Checkpoint 数据结构

已完成以下模型语义：

- `Checkpoint` 记录 `checkpointId`、`latestVersion`、`currentPublishedVersion` 和 `ownerUserId`。
- `CheckpointVersion` 记录不可变的版本详情，并携带 `checkpointId`、`version` 和 `ownerUserId`。
- `CheckpointDraft` 记录当前用户草稿、草稿版本、所有者和审核状态。
- 草稿状态当前包括“未提交审核”和“审核中”。
- Sample 数据已迁移到 `data/seeds/`；用户资料选项迁移到 `config/`。

### 3. Checkpoint Draft Repository 闭环

已完成以下本地流程：

1. 无 `checkpointId` 的 `update(value)` 创建新草稿，并自动分配新的 `checkpointId`。
2. 带 `checkpointId` 的 `update(value)` 修改已有草稿。
3. 新草稿初始版本为 `1`；从正式版本建立的草稿版本领先当前正式版本一版。
4. 编辑、提交、撤回和删除均检查当前用户所有权。
5. 审核中的草稿被冻结，不允许继续编辑或删除。
6. 用户可以提交审核、撤回审核请求，以及删除未处于审核中的草稿。
7. `approveDraft(checkpointId)` 会检查草稿处于审核中，且草稿版本严格等于当前正式版本加一。
8. 审核通过后，草稿内容复制为新的 Public Version，Public Checkpoint 的版本指针随之更新；随后 Draft 自动前进到下一版本并恢复为“未提交审核”。
9. 当前审核器是固定返回通过的模拟函数，保留在流程中作为未来真实审核实现的替换点。

当前边界：Demo 页面会在提交审核后直接调用模拟审核通过函数。该调用仅用于本地闭环演示；真实系统中必须移至可信服务端或审核端，不能由普通客户端决定审核结果。

Checkpoint Editor 当前已完成：

当前图片边界：本地保存路径只能保证当前设备上的 Demo 展示，不能跨设备使用。未来接入后端时，需要先上传图片，再把服务端或云存储资源标识写入版本数据。
