# 崇明青少年户外探索平台进度总结

## 一、项目背景情况

### 项目定位

项目当前目标为可交互 Android 演示原型，以具体、可定位的“打卡点”为核心内容单位，服务崇明户外探索场景。用户可发现打卡点、组织路线、创建安排并寻找同行者，形成从内容发现到实际出行的连续流程。

### 当前交付边界

- 仅开发 Android 单机演示原型；
- 使用本地持久化数据和模拟用户；
- 真实实现打卡点、路线、安排和邀请等核心状态变化；
- 当前不实现服务端、真实账户、多用户实时通信、真实地图、自动审核和云端同步；
- 数据访问仍保留 Repository 边界，未来可增加远程数据源；
- 轻量 Compose UI 修改默认不自动执行 Gradle 构建，由用户在手机上运行并反馈；依赖、Room、导航重构及交付前验证仍需执行构建检查。

## 二、项目现状

### Android 工程与技术栈

工程位于 `Chongming/`，采用单 Activity Compose 架构：

- Kotlin；
- Jetpack Compose 与 Material 3；
- Navigation Compose；
- Gradle Kotlin DSL 与 Version Catalog；
- Room、Repository、ViewModel 尚未加入；
- `compileSdk/targetSdk = 36`，`minSdk = 24`；
- AGP 9.0.1、Gradle 9.1.0、Kotlin 2.0.21；
- Navigation Compose 2.9.8。

当前 `libs.versions.toml` 中 `composeBom = "2024.09.01"`。此前版本诊断确认项目实际需要对齐 Compose 1.9.2，建议的 BOM 为 `2025.09.01`；当前值疑似手动修改时年份写错，尚未修复或重新验证。

### 主界面结构

`MainActivity` 只负责设置 Compose 内容，应用导航由 `MainScreen` 中的 `NavHost` 管理。

主页面使用 `MainScaffold`，底部暂定四个页签：

- 发现；
- 收藏；
- 我的；
- 编辑。

页签目前通过 `selectedIndex` 与状态提升完成切换，尚未全部建成 Navigation 目的地。页签图标仍是文字占位符。

### Navigation 结构

当前已建立真实的 Navigation Compose 返回栈：

```text
NavHost
├── main
│   └── MainScaffold + BottomBar
└── checkpoint/{checkpointId}/{version}
    └── CheckpointDetailScreen
```

点击发现页中的打卡点卡片时，使用 `(checkpointId, version)` 构造详情路由；详情页通过 `popBackStack()` 返回。详情目的地位于主 Scaffold 外，因此进入详情后主 BottomBar 不显示。

当前仍使用 `findSampleCheckpoint()` 从内存示例数据解析导航参数。未来应改为 ViewModel/Repository 按版本引用读取。

### 发现页

发现页当前包含两类视觉内容：

1. 活动 Banner：
   - 使用 `HorizontalPager`；
   - 16:9 宽幅卡片；
   - 支持横向分页吸附；
   - 下方使用 `PagerState.currentPage` 显示居中的圆点指示器；
   - 圆点间距由 `Arrangement.spacedBy(6.dp)` 控制。
2. 推荐打卡点：
   - 使用 `LazyVerticalGrid(GridCells.Fixed(2))`；
   - 一行两张卡片；
   - 图片比例为 4:3；
   - 显示单行标题、单行位置和单行标签；
   - 超出宽度时使用 `TextOverflow.Ellipsis`；
   - 发现页不显示 `shortText`，详情页完整显示。

当前活动和打卡点图片均复用启动图作为占位资源；示例地点、坐标、时间和文字只用于排版，不视为正式内容数据。

### 打卡点详情页

已创建独立的 `CheckpointDetailScreen.kt`，包含：

- 独立 Scaffold 与返回顶栏；
- 16:9 大图；
- 完整标题、位置、标签和一句话正文；
- “加入路线”和“创建安排”按钮；
- Preview 示例。

两个业务按钮当前为空实现。

### Checkpoint 数据边界

已确定并创建以下领域数据类：

#### Checkpoint

保存稳定信息：

- `id`；
- `authorUserId`；
- `currentPublishedVersion`；
- `createdAtEpochMillis`。

#### CheckpointVersion

保存审核通过后不可变的版本内容：

- `(checkpointId, version)` 作为版本引用；
- `location`；
- `title`；
- `shortText`；
- `imageId`；
- `tagIds`；
- `publishedAtEpochMillis`。

#### CheckpointLocation

- 经纬度；
- 位置名称；
- 坐标体系；
- 当前坐标体系枚举包含 `WGS84` 和 `GCJ02`。

### 已确认版本原则

- 草稿编辑或提交审核不递增公开版本；
- 首次审核通过生成 version 1；
- 已发布内容的修改审核通过后生成下一不可变版本；
- 审核拒绝不递增版本；
- 历史版本不作为数组嵌入 `Checkpoint`，而应由未来数据库中的独立版本表保存；
- `Checkpoint.currentPublishedVersion` 指向当前公开版本；
- 发现页通过 Checkpoint 与当前版本的联表查询获取展示数据；
- Schedule 保存 `(checkpointId, version)` 引用，不复制完整 Checkpoint 内容；
- 采用版本引用的前提是历史版本永久可检索；
- 已被 Route 或 Schedule 引用的版本不可物理级联删除，未来使用归档或软删除；
- Route 的不可变版本也应引用确定的 Checkpoint 版本；
- 用户导入路线后，复制并定制的是个人路线结构，节点仍可引用不可变 Checkpoint 版本。
